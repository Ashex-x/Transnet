# Transnet 服务交付计划

English: [Transnet service delivery plan](../docs/todo.md)

本计划将权威的 [Transnet 服务设计](transnet_cn.md) 转化为按顺序执行且可验证的交付切片。它跟踪仓库的实际状态，而不是愿景：仅当代码、测试和适用的合同已同步时，任务才能勾选。

状态：活跃的实施计划。翻译和模型支持的查询当前可运行；规范存储、发布锁定检索和扩展的无状态操作尚未组合进可执行程序。

## 交付规则

- 每个切片都必须保持服务边界：Transnet 仅拥有规范语言知识，不拥有用户或产品状态。
- 按顺序完成里程碑。可以提前试验后续里程碑，但在前置退出标准通过前不得发布。
- 以端到端切片交付领域类型、port、适配器、运行时组合、HTTP 行为、可观测性、测试和文档，不得将孤立层的完成视为交付。
- 明确标记运行时可用性。目标 OpenAPI 包含路由并不表示该路由已启用。
- 合同、配置字段或进程边界变更时，同步更新中英文文档。

## 已验证基线

- [x] 私有 loopback HTTP 进程、请求边界、精确来源 CORS、请求 ID、健康探针、优雅停机和脱敏结构化 trace。
- [x] 基于长度的翻译 provider 路由、有界弹性和闭合运行指标。
- [x] 默认可执行程序中基于模型的结构化词汇查询。
- [x] 规范查询、词义详情、内容发布和有界图读取的库基础与进程内测试适配器；这些依赖注入的能力并非生产存储组合。
- [x] 翻译、规范查询、词义详情和有界图读取的目标人工合同与 OpenAPI。
- [ ] 生产 MySQL 与 Qdrant 适配器、摄取管道、成对发布激活和完整目标 wire 语义。

## 里程碑 0：强制无状态边界

这是所有新存储与 API 工作的前置条件。不能让现有的产品所有基础意外成为服务承诺。

- [ ] 从 Transnet 中删除学习者档案、历史、已保存词汇、掌握度、调度、练习会话、图布局和私有反馈的领域、应用、port 和适配器代码。
- [ ] 删除可能保留请求查询或 provider 结果的异步查询作业和持久工作路径；查询执行仅限于有界请求生命周期。
- [ ] 从请求类型、provider schema、响应和测试中删除过渡性的用户导向查询字段与章节，包括学习者级别、单词历史和练习预览。
- [ ] 从公开规范图形状中删除图反馈能力以及其他不属于规范证据的产品所有元数据。
- [ ] 拒绝 Cookie、终端用户 Bearer 凭据、用户或账户标识、私有状态字段和未知字段，且不回显其值。
- [ ] 审计日志、trace、指标、缓存、队列、Debug 格式化和错误，确保请求文本、上下文、provider body、凭据、调用方身份和音频不会跨越持久化边界。只缓存以规范 ID 定址的发布锁定规范数据。
- [ ] 删除或重写将 Transnet 描述为个人状态所有者的测试和源码注释，然后同步人工与机器合同。

退出标准：没有可达路由或可复用公开服务 API 接受产品所有状态；没有请求 payload 或派生请求向量能到达持久 port；边界拒绝和非持久化测试通过。

## 里程碑 1：冻结请求语义与路由

- [ ] 实现服务接口定义的共享成功与错误 envelope、请求元数据、严格未知字段拒绝、语言 tag 验证和安全状态映射。
- [ ] 实现版本化的请求内 normalizer，包含 Unicode 规范化、语言感知大小写折叠、空白与标点处理、有意义符号保留和有界派生形式。
- [ ] 实现类型化意图路由：置信的词汇单元使用规范查询，子句、句子、篇章和模糊短片段默认翻译。
- [ ] 使 POST `/translate` 与目标响应一致，包括检测语言、格式与语域处理，以及不超过两条有实质价值的单句提示。
- [ ] 使查询、词义、图和邻居的请求与响应 schema 符合目标合同；在做出并记录兼容性决策后删除过渡 wire 别名。
- [ ] 通过 readiness 准确报告路由可用性以及必需与可选依赖，不暴露基础设施细节。
- [ ] 根据适用性，将响应元数据锁定到 schema、normalizer、模型、检索配置和内容发布版本。

退出标准：合同测试覆盖每个已启用路由和错误 envelope；路由评估覆盖单词、词汇短语、符号、句子、篇章和模糊片段；运行时文档标明确切的已启用子集。

## 里程碑 2：构建规范 MySQL 核心

- [ ] 为卡片、词义、形式、别名、定义、翻译、发音、形态、例句、用法注释、规范领域、证据、不可变修订和发布 manifest 定义 migration 与生产 repository 适配器。
- [ ] 在文档化的版本策略下使稳定卡片、词义、领域、证据和修订 ID 具有确定性；不得使用规范化查询字符串作为身份。
- [ ] 先执行精确规范与别名解析，再生成有界屈折、拼写更正、转写或宽松别名候选。
- [ ] 实现草稿暂存、冲突检测、证据与许可验证、隔离、作为新修订的修正和不可变保留。
- [ ] 从 MySQL 返回简洁的发布锁定基础卡，不要求模型或 Qdrant。
- [ ] 添加配置、readiness 探针、migration、测试 fixture 和失败映射，不暴露凭据或存储内部细节。

退出标准：能够可复现地构建暂存的规范发布；精确查询和词义读取可仅依赖 MySQL 工作；migration、冲突、证据、隔离与不可变性测试通过。

## 里程碑 3：构建 Qdrant 投影与安全检索

- [ ] 仅从已发布规范内容构建确定性不可变 collection，先构建节点 collection，再构建边 collection。
- [ ] 存储命名跨语言稠密向量和稀疏词汇向量，payload 包含发布、语言、方言、地区、时期、领域、证据和验证状态。
- [ ] 校验每条有类型边的端点存在性、方向、限制、证据、置信度、验证状态和发布兼容性。
- [ ] 实现精确、稀疏、稠密、混合、端点和重排检索，在限制数量前应用过滤器。
- [ ] 实现浅层单根图扩展和不透明有界分页；保持分类与强度维度及其他有类型关系的区分。
- [ ] 在存储、排名、响应形状和评估中分离已验证关系与探索性关联。相似度不得确立规范事实。
- [ ] 添加生产 Qdrant 适配器、配置、readiness 探针、确定性重建测试和依赖失败映射。

退出标准：可以从一个 MySQL 发布使用稳定哈希重建 Qdrant；检索锁定发布且过滤安全；对抗测试证明向量近邻永远不会被提升为已验证关系。

## 里程碑 4：激活成对发布并组合运行时

- [ ] 激活前对账 MySQL 修订、Qdrant 节点与边哈希、端点覆盖、embedding 元数据、schema 兼容性和经认证的 manifest。
- [ ] 为新请求原子选择一对兼容的 MySQL/Qdrant 发布，同时运行中请求仍锁定到它们开始时的发布。
- [ ] 通过选择未变的已保留发布对实现隔离、失败发布清理、修正、保留和回滚。
- [ ] 将生产 MySQL 与 Qdrant 适配器组合进可执行程序，仅当必需依赖就绪时启用规范查询、词义、图和邻居路由。
- [ ] Qdrant 不可用时返回显式的仅 MySQL 降级查询响应；不得用生成的声明填充缺失关系。
- [ ] 演练过期、部分、不匹配、不可用和回滚状态，不得部分激活或跨发布读取。

退出标准：已对账发布对可发布、服务、安全降级并无需改写即可回滚；readiness 和响应元数据准确报告活跃能力与发布。

## 里程碑 5：落地模型辅助响应并对核心发布设门

- [ ] 将翻译、路由、词汇分析、关系解释和策展拆分为具有版本化 schema、prompt、限制和评估标准的有界模型角色。
- [ ] 仅使用合格的发布锁定规范记录构建请求内上下文，并将请求文本、检索材料和模型输出视为不可信数据。
- [ ] 添加确定性结构化输出验证、有界修复、显式不确定性和修复耗尽后的安全失败。
- [ ] 防止生成文本和相似度分数在发布工作流之外成为规范内容。
- [ ] 为路由、翻译、词汇解析、检索、证据、文化范围、prompt injection、依赖降级和 schema 兼容性构建版本化评估数据集。
- [ ] 证明请求不会持久化到 MySQL、Qdrant、缓存、日志、trace、指标、队列、备份或 provider 遥测。
- [ ] 将格式化、lint、测试、rustdoc、合同检查、发布对账、回滚演练和中英文档检查作为发布门槛。

退出标准：设计和 [质量保证指南](guides/quality-assurance_cn.md) 中的所有核心质量场景在已组合可执行程序上通过，已启用合同可用于版本化发布。

## 里程碑 6：添加扩展无状态操作

仅在核心发布门槛通过后开始。每个操作都是独立的合同和交付切片，在自身的隐私、质量与失败标准通过前保持禁用。

- [ ] 为调用方提供的规范目标、目的、难度和限制指定并实现无状态练习生成；返回材料和 rubric，不创建队列或尝试记录。
- [ ] 指定并实现写作评估，包括保留意义的修正、可选的自然替代、至多两条优先解释和重试 prompt。
- [ ] 指定并实现有范围的沟通与文化指导，明确关系、场景、媒介、方言和地区边界。
- [ ] 指定并实现带标签的参考 TTS，使用有界方言、声音、语速和用途选项。
- [ ] 指定并实现有界发音分析，包括音频质量与对齐检查、至多两个可理解性目标、证据不足时的不确定性，且不保留音频。
- [ ] 为每个已启用操作添加独立模型与 analyzer 版本、运行限制、评估数据集、readiness 行为和发布门槛。

退出标准：每个已启用操作均可复现、经过合同测试、明确公告并已证明无状态；产品仍是练习、尝试、反馈记录、音频保留、掌握度和复习调度的唯一所有者。

## 服务完成定义

- 句子获得翻译优先响应，置信解析的词汇单元获得规范词义特定响应。
- MySQL 基础卡在没有 Qdrant 时仍然有用，图结果永远不会将相似度提升为无支持事实。
- 内容发布仅以已对账的 MySQL/Qdrant 对激活，并通过不可变选择回滚。
- Transnet 不存储请求文本、上下文、音频、调用方身份或用户相关状态，也不通过可观测性或错误披露它们。
- 每个已启用响应都标识在 provider 确定性限制下复现该响应所需的版本和发布。
- 中英文设计、人工合同、机器合同、配置、源码注释和测试均与运行时行为一致。

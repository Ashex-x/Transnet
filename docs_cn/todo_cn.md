# Transnet 服务交付计划

English: [Transnet service delivery plan](../docs/todo.md)

本计划编排 [Transnet 服务设计](transnet_cn.md) 的实现，记录目标工作而非已实现行为。

## 当前基线

- [x] 私有 HTTP 进程、健康探针、请求边界、请求 ID、优雅关闭和脱敏 trace。
- [x] 翻译 provider 路由、弹性和结构化词汇查询基础。
- [ ] 规范 MySQL 内容、Qdrant 关系发布和完整无状态服务合同。

## 阶段 1：无状态 HTTP 语义

- [ ] 实现目标翻译 envelope 和翻译优先路由。
- [ ] 实现请求内词汇单元与句子/篇章路由。
- [ ] 实现目标规范查询、词义、图和邻居响应 schema。
- [ ] 拒绝用户标识、Cookie、终端用户 Bearer token 和不支持的可变产品路由。
- [ ] 确保请求文本和上下文不进入日志、遥测、缓存或持久工作。

## 阶段 2：规范内容与发布

- [ ] 实现 MySQL 卡片、词义、别名、领域、证据记录、不可变修订和发布激活。
- [ ] 实现确定性 ID、发布校验、隔离、修正和回滚。
- [ ] 构建具有命名稠密和稀疏向量的不可变 Qdrant 节点/边集合。
- [ ] 激活前对账端点覆盖、内容哈希、嵌入元数据和经认证 manifest。

## 阶段 3：检索与图安全

- [ ] 实现精确、混合、端点和有界单根图检索。
- [ ] 保持已验证有类型边与探索性向量关联分离。
- [ ] MySQL 可用而 Qdrant 不可用时实现显式降级响应。
- [ ] 强制发布、语言、方言、地区、时期、领域、证据和验证状态过滤。

## 阶段 4：可靠性与合同质量

- [ ] 设计并实现无状态练习生成、写作评估、参考语音和发音分析操作，且不增加用户持久化。
- [ ] 版本化 prompt、schema、模型、normalizer、检索配置和内容发布。
- [ ] 对无效结构化 provider 输出增加确定性校验和有界修复。
- [ ] 测试输入不持久化到存储、缓存、日志、trace、指标、队列和向量。
- [ ] 以词汇解析、检索、证据、安全、依赖降级、激活、回滚和 schema 兼容性作为发布门槛。
- [ ] 使英文/中文文档、OpenAPI、源码注释和测试与服务合同保持同步。

## 完成定义

- 句子得到翻译优先响应，词汇单元得到规范词义特定响应。
- MySQL 基础卡在没有 Qdrant 时仍然有用，图结果绝不将相似度提升为无支持事实。
- 内容发布仅以经对账的 MySQL/Qdrant 对激活，并能在不改写的情况下回滚。
- Transnet 不存储请求文本、上下文、调用方身份或用户相关状态。
- 英文和中文文档、人类合同、机器合同、源码注释和测试一致。

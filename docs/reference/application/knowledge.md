# Knowledge application

中文：[知识 application](../../../docs_cn/reference/application/knowledge_cn.md)

This module owns sense resolution, domain assessment, release-pinned retrieval, relationship ranking, page composition, and deterministic projection for word and established-phrase requests.

Status: current canonical lookup uses read-only retrieval ports and assembles each card within the request. Query-derived snapshot and graph-topology caches and their public contracts have been removed. The bounded domain-assessment foundation and strict outbound inventory client are implemented for the separately optional relationship-page material authority. A bounded root-retrieval application boundary composes injected canonical and retrieval ports. Guided-view and path-search services verify immutable projection proofs and hydrate exact canonical assertions; the executable composes their public routes atomically when knowledge is enabled and the active release trio validates. An optional atomic material-source seam assembles and serializes a release-bound relationship page beside a resolved lexical translation, including explicit canonical-only degradation. The default process does not install that material seam or advertise `relationship-page-v1`: production still lacks the root resolver and canonical/retrieval authority composition needed to supply complete page material truthfully.

The canonical-only service selects one authority-owned release pin, then composes reviewed translation candidates, deterministically ranked lexical candidates, and unambiguous sense details through a read port. It forms the existing lookup-card type with a canonical-only content pin; it does not fabricate a vector collection or treat intentional lexical-only operation as vector degradation. The executable constructs and retains this dependency only when explicitly configured probes the active release for readiness, and exposes it through the frozen BasicCard lookup and release-pinned sense routes. The external island-port server still needs the matching internal contract. Request-local lookup spellings are bounded and deduplicated: the baseline normalized form is strongest, and cautious whitespace or surrounding-punctuation variants are lower-priority spelling candidates. Published alias, morphology, transliteration, and semantic membership remains authority-owned rather than guessed from a query string.

The public release-pinned sense follow-up uses the caller's `CanonicalReleasePin` and sense ID without selecting active content again. Source attribution carried by existing candidate/evidence types comes from the authority's reviewed release metadata, never a source-ID-derived label. The HTTP boundary exposes this seam through `POST /api/v1/senses/get`; the application module remains independent of transport DTOs.

The offline `KnowledgePublicationService` is a separate application boundary over `KnowledgePublicationPort`. It validates one immutable release-pinned plan and deterministically plans the largest consecutive node and edge prefixes that satisfy both the 256-point limit and the port's pure worst-case 1 MiB wire inspection. Final batch boundaries define ordinals, hashes, fingerprints, and resume interpretation. It then begins or replays the build intent, reads authoritative status as the only resume-progress source, submits only remaining node batches before node freeze, then remaining edge batches before edge freeze, and finally reconciles the frozen artifacts. Explicit status inspection and idempotent abort are available through the same offline boundary; neither stores progress nor deletes immutable artifacts. Only a successful authority reconciliation may return `PublicationActivationCandidate`; activation and rollback selection remain external authenticated publisher/control-plane operations through island-port and are never part of the online request runtime.

## Resolution and assessment

Normalization creates bounded language-aware lookup forms but never serves as canonical identity. Resolution uses the closed order exact canonical -> exact published alias -> bounded inflection -> bounded spelling correction -> bounded transliteration -> semantic nomination. A score or vector signal cannot promote a lower class above an eligible higher class. Only candidates in the best available class survive; one sense resolves, multiple distinct senses require clarification or preserved ambiguity, and no candidate is an explicit not-found result. Materially plausible homographs, parts of speech, phrase-level meanings, and field-specific senses remain separate.

Every non-semantic authority match is verified against the release-pinned candidate before ranking. Its stable form ID, exact stored surface form, active lifecycle, lexeme ownership, and form role must support the claimed match class. Contradictory provenance fails the canonical-only read; it cannot silently become not-found or receive a weaker class. Intentional canonical-only operation is reported with its canonical release pin and is distinct from hybrid retrieval's explicit vector-degraded outcome.

Domain assessment uses a bounded published inventory under the caller's single immutable release pin and returns `existing`, `proposed_new`, `general`, or `uncertain`. The authority supplies multilingual labels, aliases and definitions, inclusion and exclusion scope, canonical broader IDs, and a knowledge profile with fact families, languages, verified count, and `seed`, `partial`, or `curated` coverage. Deterministic validation accepts selected stable IDs only from that exact allowlist.

Any inventory call failure produces `uncertain`; it cannot prove that a domain is new. A successful but incomplete catalog also cannot produce `proposed_new`. Only an explicitly complete, strictly ordered catalog permits a structured proposal; its broader IDs must belong to the supplied allowlist, and its exact canonical language-plus-label pair must not collide with a supplied label or alias. The proposal has no stable identity, remains request-local, is never persisted by this flow, and appears only where a later full response permits it. The application exposes no live domain-creation capability.

## Retrieval and composition

Vector similarity nominates candidates and never establishes a fact. Every displayed canonical node, edge, evidence item, and revision is hydrated from authoritative structured data under the request's release pin. Ranking filters by sense, domain, language, region, period, conditions, and evidence policy without changing identity, direction, provenance, or verification state.

Root retrieval always completes canonical resolution first. Not-found and same-precedence ambiguity stop before embedding, lexical encoding, or retrieval-data access. Ambiguous candidates must be distinct lexical-sense roots with valid bounded labels under the same caller and execution release pin. One resolved root freezes the release for every later operation; a caller pin, projection echo, or hydrated record from another release fails closed. Transnet generates the 1,024-dimensional dense signal and `query-lexical-input-v1` sparse signal ephemerally, and retrieval-data receives only vectors and structured filters rather than query text. Exact dense artifact/dimension and sparse release/encoder/input receipts must match the configured release-pinned execution specification before ranking.

Every nominated projection pointer is batch-hydrated through canonical-data before it can enter the validated superset. Missing hydration is explicit partial-publication coverage; mismatched family, identity, sense, bounded label, or release data fails closed. Deterministic reranking uses bounded integer scores, the exact retrieval-data mechanism catalog, and canonical node identity as the final tie-breaker. Duplicate mechanisms fail before scoring rather than inflating rank. The canonical root is `verified`; similarity nominations remain `exploratory` even when their node identities hydrate successfully, and this flow creates no `inferred` claims. When vector retrieval is unavailable, the outcome is explicitly canonical/MySQL-only with no invented relationship or hidden vector success.

A model may organize supplied facts and write concise explanations, but cannot invent endpoints or change fact metadata. Deterministic validation checks every reference. Empty or weak sections are omitted.

Canonical knowledge is an assertion graph, not a stored tree. A versioned relation registry defines participant roles and which n-ary assertions permit a binary traversal projection. The implemented closed policies for meaning, contrast, usage, form, origin, and domain derive exact relation families, hydratable endpoint families, depth, item budget, and display-evidence eligibility without accepting caller-supplied graph controls. Mechanism and application remain unavailable until the registry exposes explicit technical relations; weak topical association never proves either lens. Every non-root guided-view item must retain a one-to-three-hop, cycle-free path of independently evidenced assertion projections back to the verified root. A step is constructible only from exact canonical hydration under the full release pin and follows the declared source-to-target traversal; reverse travel requires a separately declared inverse traversal. Grounded request-local explanation may remain `inferred`, while similarity-only `exploratory` material cannot enter the factual view or serve as a path step. Ordered branches partition the non-root items, truncation agrees with cursor presence, and response projection always uses the level bound into the request. `knowledge/paths` admits at most three distinct, ordered paths of at most three hops and uses `no_verified_path` as a successful bounded-search outcome rather than a global absence claim.

The guided-view service keeps one caller-supplied canonical release pin and one exact node/edge collection proof for the whole expansion. Retrieval-data supplies only verified neighbor nominations; canonical-data must return the exact assertion revision, declared traversal, evidence lineage, display-safe endpoint records, and any complete semantic scale. Missing nominated canonical records are reported as partial publication, while transport unavailability is a separate dependency failure. Ranking uses the frozen lens relation order, endpoint-family order, and canonical identity, never a similarity score.

The path-search service first hydrates and type-checks both selected roots from canonical data, then performs a deterministic directed breadth-first search with a 50-node expansion budget, a 12-page retrieval budget, three-hop paths, and at most three results. Useful-path policy v1 selects explicit semantic, taxonomy, part-whole, form, origin, construction, and scale relations while excluding weak topical `associated_with` edges. It requests only verified direct neighbors under the request's exact canonical release, immutable node and edge collection identities and hashes, registry revision, and frozen input contracts. Retrieval order does not control output order: candidates and completed paths use stable publisher identities as tie-breakers, and a path cannot revisit a node.

Every nominated edge is batch-hydrated as the exact assertion revision and declared binary traversal before frontier expansion. The service requires the projection edge, relationship revision, assertion identity and revision, traversal identity, typed declared source and target, registry revision, and non-empty API-redistributable evidence to agree. It follows only the declared source-to-target direction and never accepts similarity edges as proof. Missing hydration, pagination or expansion exhaustion, stale pins, malformed projection echoes, dependency failure, timeout, or cancellation is an explicit failure; none may be converted to `no_verified_path`. That normal empty outcome is returned only after the complete eligible bounded search ends without a hydrated connection.

`brief`, `standard`, and `full` are projections of the same validated superset. Response level changes breadth, not fact choice or truth status.

The relationship-page domain foundation owns that larger lexical superset without adding transport orchestration. It binds a BasicCard or concept-summary authority receipt, closed domain profiles, exact hydrated facts, complete semantic scales, deterministic relationship groups and paths, labeled request-local generated or inferred material, exploratory nominations, explicitly requested alternatives, and offline-only gap nominations to one root and full release pin. A displayed relationship must start with the exact hydrated fact it names, pass the full-pin path validator, and use the closed relation-to-group policy; unsupported mechanism and application groups fail closed. Complete scales project atomically with their admitted taxonomy group. Alternatives bind the owning stable translation ID and order before deterministic selection. Gap nominations are opaque and non-authoritative, and the online projection deliberately has no gap field. The application composer accepts outputs of the domain, view, and path services, rejects mixed roots or releases, discards non-verified view nominations from factual groups, and reports an explicit canonical-only outcome when no verified relationships are available. It embeds the projection only beside a word or established-phrase translation result; there is no separate page route. Content-bearing debug output is redacted.

## Verification

Test candidate precedence, ambiguity, closed domain outcomes, unavailable inventory, release consistency, hydration, relation-registry compatibility, n-ary participant validation, lens budgets, path evidence, cycle-safe presentation, evidence filtering, graph bounds, hallucinated references, empty sections, and projection monotonicity.

# Configuration

中文：[配置](../../docs_cn/guides/configuration_cn.md)

The process reads `config/transnet.toml` relative to the Cargo manifest, independent of the shell working directory. A trusted deployment may set `TRANSNET_CONFIG` to select another file; the production systemd unit uses this mechanism so an immutable uploaded binary does not depend on its build checkout path.

The implemented target listener configuration uses `socket_path = "/run/transnet/transnet.sock"`, `socket_mode = "0660"`, and an operator-managed socket group. The path must be absolute, at most 107 bytes, and contain neither whitespace nor a `..` component; the mode must be four-digit octal from `0600` through `0770`. The supervisor must create the parent as a real directory with the intended owner and group. Transnet refuses non-socket entries and active sockets, removes an existing socket only after a refused connection proves it stale, applies the configured mode after binding, and removes only the socket inode it owns during shutdown. Structured and vector data clients use island-port at `/run/island-port/island-port.sock`. Socket paths are deployment settings; API namespaces are fixed.

Transnet serves HTTP/1.1 only on the required absolute `socket_path` and drains accepted connections for up to 30 seconds during shutdown. `host` and `port` are rejected legacy keys. `RUST_LOG` overrides `log_level`; `log_format = "json"` selects newline-delimited JSON and other values select compact text. Debug builds write `logs/debug/transnet.log`; release builds write `logs/release/transnet.log`.

`[http]` configures only `max_request_body_bytes`. The body limit applies before JSON is buffered and defaults to 1,048,576 bytes. CORS keys are rejected because browsers call a product gateway, not Transnet; end-user authentication remains owned by island-port.

`[translation]` configures default per-attempt timeout, retry count after the first attempt, and retry delay for generation. Provider-specific overrides take precedence.

`[gemma4]` configures the single OpenAI-compatible Gemma4-27B `base_url`, `model`, and `api_key`. Real credentials must be provisioned without committing them to Git; parsed credentials are redacted from Rust `Debug` diagnostics and are used only for outbound provider requests.

These tables describe the retained provider-adapter compatibility settings. The public application boundary already exposes one generation abstraction with closed fast/reasoning profiles; provider-specific configuration remains internal until the adapter constructor is consolidated. Request-local embedding and live-retrieval settings stay absent from production configuration until complete authorities can be composed and attested.

Provider clients connect directly to their configured endpoints and do not inherit operating-system or environment proxy settings. This keeps loopback and private model traffic, including bearer credentials, out of unrelated proxy processes.

`[provider_resilience.gemma4]` configures generation bounds. `timeout_seconds`, `max_retries`, and `retry_delay_ms` may override `[translation]`; the remaining fields bound retry delay, concurrency, and circuit behavior.

Only request timeouts, connection-establishment failures, `429`, `500`, `502`, `503`, `504`, and unusable successful envelopes are retried. A valid `Retry-After` header is used instead of the configured retry delay, subject to `max_retry_delay_ms`; other client, server, and ambiguous transport failures fail without another request. An open circuit and full bulkhead fail the affected provider request promptly and map to the existing unavailable response.

Provider traces contain only the static provider boundary, operation name, attempt number, outcome class, status code when available, elapsed time, and retry delay. The process exposes in-memory redacted provider counter snapshots through Rust service APIs; no raw query, context, generated answer, provider body, credential, or identity is included in provider telemetry.

Target telemetry additionally records only the closed inference profile (`fast` or `reasoning`), input-kind category, and whether a reasoning escalation occurred. It never records image data, prompts, hidden reasoning, embeddings, live-search queries, fetched content, or generated output.

The repository-owned logical telemetry policy now freezes the closed modes `disabled` and `configured`, queue capacity from 1 through 4,096 records, export timeout from 1 millisecond through 5 seconds, and separate deterministic success/failure sampling rates from 0 through 10,000 basis points. Sampling occurs before queue admission and never inspects content; metric and telemetry-drop records are never sampled. These types are not active runtime settings: the current strict configuration still rejects a `[telemetry]` table, constructs no exporter, and has no collector dependency. Collector transport, endpoint, authentication, framing, acknowledgement, and retry behavior require a separate deployment-owned contract before configuration keys or an adapter are added. Runtime exporter failure will remain best effort and cannot affect readiness or a business response, while invalid future configuration will fail startup. Audit-sink settings belong to the offline publisher composition. See the [observability contract](../reference/observability.md).

The translation operation uses one neutral generation boundary backed by `[gemma4]` and `[provider_resilience.gemma4]`. TranslateGemma, length routing, and provider-specific compatibility sections are rejected as unknown configuration.

`[canonical]` is an opt-in canonical-only production read dependency. The checked-in configuration sets `enabled = false`: the process constructs no island-port client, model translation behaves as before, and readiness does not claim canonical availability. To enable it on a Unix host, set `enabled = true`, an absolute `socket_path` for island-port (for example `/run/island-port/island-port.sock`), and `timeout_ms` from 1 through 30,000. The Unix socket path must be at most 107 bytes, contain no whitespace or `..` component, and is redacted from configuration Debug and errors. Missing or invalid enabled settings reject startup; enabled operation on a non-Unix host rejects startup because the production UDS transport is unavailable there.

When enabled, the process constructs the strict outbound island-port client and request-local `CanonicalReadService` used by `POST /api/v1/basic-cards/lookup` and release-pinned `POST /api/v1/senses/get`. `POST /api/v1/readyz` performs the bounded active-release read: no active release, transport failure, incompatible schema, malformed response, or timeout means not ready. A missing or outdated island-port server may leave the process running with target readiness returning `503`; it is never treated as a canonical miss or a ready capability. The socket is not a MySQL connection, and no vector/ranking version is invented. The adapter wire schema and response bound remain fixed and strict, not caller-configurable versions.

`[knowledge]` is the separate opt-in composition for guided views and bounded paths. The checked-in configuration sets `enabled = false` and `required = false`; disabled operation needs no secret and preserves the canonical-only runtime. `required = true` is valid only with `enabled = true`. Enabled knowledge reuses the successfully validated `[canonical]` island-port Unix socket and timeout for canonical, retrieval, and active-trio clients; it cannot configure a competing transport or direct database connection. Startup reads one complete active canonical/node/edge tuple, validates it once, and gives exact clones of that snapshot to both application services, the atomic route bundle, and readiness. Missing or incompatible active data prevents required startup. For optional knowledge it starts without knowledge routes or lenses, keeps canonical readiness authoritative, and reports retrieval/projection unavailable.

An enabled knowledge runtime selects exactly one stable cursor-secret reference: `cursor_secret_env = "TRANSNET_KNOWLEDGE_CURSOR_SECRET"` or `cursor_secret_file = "/run/secrets/transnet-knowledge-cursor"`. The environment-variable name must contain only uppercase ASCII letters, digits after the first character, and underscores. A file path must be absolute, must not be a symlink, and must identify a regular root-owned file whose group/other permission bits are all clear, such as mode `0400` or `0600`; its immediate parent directory must also be root-owned and not group/other writable. Transnet opens the file once without following a final symlink, validates that open descriptor, and reads from the same descriptor. File loading removes conventional trailing CR/LF bytes. Loaded material must contain 32 through 4,096 bytes. Never put the secret value itself in TOML; configuration Debug, enabled-setting Debug, loading errors, and parse errors redact both references and values.

Transnet-side canonical public delivery is implemented by the two routes above, including release/schema failure mapping and attribution/evidence projection. The island-port canonical server, production MySQL migrations, publisher/write operations, real publication, activation, rollback and quarantine, immutable old-release serving verification, and island-port/MySQL end-to-end acceptance remain external target capabilities. Knowledge embedding configuration is intentionally absent until its artifact identity, dimension, input contract, endpoint, timeout, credentials, and redaction can be validated together. See the [canonical-data endpoints](../interfaces/canonical-data.md), [retrieval-data endpoints](../interfaces/retrieval-data.md), and [Transnet](../transnet.md) contracts. Never place credentials or request content in the checked-in file.
